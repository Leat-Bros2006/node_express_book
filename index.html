Node.js & Express.js 1. Introduction to Node.js

1. សេចក្តីផ្តើមអំពី Node.js & ការដំឡើង

1. Definition (និយមន័យ):

Node.js គឺជា JavaScript Runtime Environment ដែលអនុញ្ញាតឱ្យយើងអាចដំណើរការកូដ JavaScript នៅខាងក្រៅ Browser (នៅលើ Server ឬកុំព្យូទ័រផ្ទាល់) ដោយប្រើប្រាស់ V8 Engine របស់ Google Chrome។

2. មុខងារ និងពាក្យបញ្ជាសំខាន់ៗ:

  • node -v (ពិនិត្យជំនាន់)៖ ពាក្យបញ្ជាសម្រាប់ឆែកមើលជំនាន់ Node.js ដែលបានដំឡើងលើម៉ាស៊ីន។
  • node app.js (ដំណើរការកូដ)៖ ប្រើសម្រាប់រត់ឯកសារ JavaScript (.js) នៅក្នុង Terminal។
  • console.log() (បង្ហាញលទ្ធផល)៖ បោះពុម្ពទិន្នន័យ ឬសារពិនិត្យកំហុស (Debug) ចេញមកលើផ្ទាំង Terminal។

លក្ខណៈពិសេសស្នូលរបស់ Node.js:

  • V8 Engine៖ បម្លែងកូដ JavaScript ទៅជា Machine Code បានយ៉ាងលឿនបំផុត។
  • Non-blocking I/O៖ អាចទទួលសំណើ (Requests) ពីអ្នកប្រើប្រាស់ច្រើននាក់ព្រមគ្នាដោយមិនរង់ចាំគ្នា។
  • Full-Stack JavaScript៖ ប្រើភាសា JavaScript តែមួយទាំងផ្នែក Frontend និង Backend។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលយើងចង់បង្កើត Server-Side Web Application, RESTful APIs, Real-time Chat Apps ឬប្រព័ន្ធគ្រប់គ្រងទិន្នន័យដែលត្រូវការល្បឿនលឿន។

4. Syntax (ទម្រង់កូដបង្កើត File ដំបូង - app.js):

// បង្កើតឯកសារឈ្មោះ app.js
const studentName = "សុខា";
const course = "Node.js & Express.js";

console.log(`សួស្តី ${studentName}! ស្វាគមន៍មកកាន់មេរៀន ${course}`);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node -v
v22.11.0
$ node app.js
សួស្តី សុខា! ស្វាគមន៍មកកាន់មេរៀន Node.js & Express.js
6. Summary (សង្ខេបមេរៀន)៖ ដើម្បីដំណើរការកូដ JavaScript លើ Server យើងត្រូវដំឡើង Node.js (ជំនាន់ LTS) រួចប្រើពាក្យបញ្ជា node ឈ្មោះឯកសារ.js នៅក្នុង Terminal។

Node.js & Express.js 2. NPM & Package Management

2. ការគ្រប់គ្រងគម្រោងជាមួយ NPM (package.json)

1. Definition (និយមន័យ):

NPM (Node Package Manager) គឺជាកម្មវិធីគ្រប់គ្រងកញ្ចប់កូដ (Libraries/Packages) របស់ Node.js ដែលភ្ជាប់មកជាមួយស្រាប់ពេលយើងដំឡើង Node.js។

2. មុខងារ និងពាក្យបញ្ជាសំខាន់ៗ:

  • npm init -y (បង្កើតគម្រោងថ្មី)៖ បង្កើតឯកសារ package.json ដោយស្វ័យប្រវត្តិសម្រាប់កត់ត្រាព័ត៌មានគម្រោង។
  • npm install <pkg> (ដំឡើង Library)៖ ទាញយកកញ្ចប់កូដមកប្រើ (ឧ. npm install express)។
  • npm install -D nodemon (Dev Dependency)៖ ដំឡើងឧបករណ៍ជំនួយពេលសរសេរកូដ (Restart Server ស្វ័យប្រវត្តិពេលកែកូដ)។

ឯកសារ និងថតសំខាន់ៗក្នុងគម្រោង NPM:

  • package.json (Config File)៖ កត់ត្រាឈ្មោះគម្រោង, Scripts និងបញ្ជី Libraries ដែលបានដំឡើង។
  • node_modules/ (Packages Folder)៖ ថតផ្ទុកកូដ Libraries ទាំងអស់ (ត្រូវដាក់ក្នុង .gitignore)។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលចាប់ផ្តើមបង្កើតគម្រោង Backend ថ្មីដំបូង ឬត្រូវការទាញយក Libraries ជំនួយមកប្រើ (ដូចជា Express, Mongoose, Dotenv)។

4. Syntax (ទម្រង់ឯកសារ package.json):

{
  "name": "my-backend-api",
  "version": "1.0.0",
  "main": "server.js",
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  },
  "dependencies": { "express": "^4.21.1" }
}

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ npm init -y
Wrote to /my-backend-api/package.json
$ npm install express
added 65 packages in 2s
6. Summary (សង្ខេបមេរៀន)៖ រាល់គម្រោង Node.js ត្រូវចាប់ផ្តើមដោយ npm init -y ដើម្បីបង្កើត package.json និងប្រើ npm run dev ដើម្បីដំណើរការគម្រោងជាមួយ Nodemon។

Node.js & Express.js 3. Node.js Module System

3. ប្រព័ន្ធ Modules ក្នុង Node.js (CommonJS vs ES Modules)

1. Definition (និយមន័យ):

Module គឺជាការបំបែកកូដ JavaScript ជាឯកសារតូចៗដាច់ដោយឡែកពីគ្នាតាមមុខងារ ដើម្បីងាយស្រួលគ្រប់គ្រង កែប្រែ និងយកទៅប្រើឡើងវិញនៅក្នុងឯកសារផ្សេងទៀត។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • module.exports (បញ្ចេញកូដ)៖ ប្រើសម្រាប់បញ្ជូន Functions ឬ Variables ចេញពីឯកសារបច្ចុប្បន្ន។
  • require('./file') (ទាញកូដមកប្រើ)៖ ប្រើសម្រាប់នាំចូល Module ពីឯកសារផ្សេងមកប្រើ។

ប្រព័ន្ធ Modules ទាំង ២ ក្នុង Node.js:

  • CommonJS (Default)៖ ប្រើ module.exports និង require() (ទម្រង់ដើមរបស់ Node.js)។
  • ES Modules (ES6)៖ ប្រើ export និង import (ត្រូវថែម "type": "module" ក្នុង package.json)។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលគម្រោងមាន Functions ច្រើន ហើយយើងចង់បំបែកកូដជាផ្នែកៗ (ដូចជា Database Config, Routes, Controllers) ដើម្បីឱ្យមានរបៀបរៀបរយ។

4. Syntax (ទម្រង់កូដ CommonJS):

// ១. ឯកសារ math.js (បញ្ចេញ Function)
const add = (a, b) => a + b;
const multiply = (a, b) => a * b;
module.exports = { add, multiply };

// ២. ឯកសារ app.js (ទាញយកមកប្រើ)
const { add, multiply } = require('./math');
console.log("ផលបូក៖", add(10, 5), "| ផលគុណ៖", multiply(10, 5));

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node app.js
ផលបូក៖ 15 | ផលគុណ៖ 50
6. Summary (សង្ខេបមេរៀន)៖ ប្រើ module.exports និង require('./file') សម្រាប់ CommonJS ឬប្រើ export និង import សម្រាប់ ES Modules។

Node.js & Express.js 4. Built-in Modules (fs & path)

4. ការប្រើប្រាស់ Built-in Modules (fs & path)

1. Definition (និយមន័យ):

Built-in Modules គឺជា Modules ដែល Node.js បង្កើតមកឱ្យប្រើស្រាប់ដោយមិនចាំបាច់ដំឡើងតាម NPM ឡើយ ដូចជា fs (គ្រប់គ្រងឯកសារ) និង path (គ្រប់គ្រងទីតាំង Folder)។

2. មុខងារ និង Methods សំខាន់ៗ:

  • fs.writeFileSync(path, data) (សរសេរ File)៖ បង្កើតឯកសារថ្មី ឬសរសេរទិន្នន័យជាន់ពីលើ។
  • fs.readFileSync(path, 'utf8') (អាន File)៖ អានអត្ថបទពីក្នុងឯកសារមកបង្ហាញ (ប្រើ 'utf8' ដើម្បីស្គាល់អក្សរខ្មែរ)។
  • path.join(__dirname, 'file') (តភ្ជាប់ទីតាំង)៖ តភ្ជាប់ឈ្មោះ Folder និង File ឱ្យត្រូវតាមប្រព័ន្ធប្រតិបត្តិការ (Windows / macOS)។

អថេរ និងវិធីប្រើប្រាស់បន្ថែម៖

  • __dirname (Current Directory)៖ អថេរពិសេសប្រាប់ពីទីតាំង Folder ដែលឯកសារកូដកំពុងស្ថិតនៅ។
  • fs.appendFileSync() (Append)៖ សរសេរទិន្នន័យបន្ថែមពីខាងចុងឯកសារដោយមិនលុបទិន្នន័យចាស់។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលត្រូវការបង្កើត ឬអានឯកសារ (Logs, JSON, Text) នៅលើ Server ឬកំណត់ទីតាំង Folder សម្រាប់រក្សាទុករូបភាពដែលអ្នកប្រើប្រាស់ Upload។

4. Syntax (ទម្រង់កូដ):

const fs = require('fs');
const path = require('path');

const filePath = path.join(__dirname, 'note.txt');
fs.writeFileSync(filePath, 'មេរៀន Node.js ងាយស្រួលរៀន!');
const content = fs.readFileSync(filePath, 'utf8');
console.log("ខ្លឹមសារក្នុងឯកសារ៖", content);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node file-demo.js

Node.js & Express.js 5. Built-in HTTP Server

5. ការបង្កើត Web Server ដំបូងដោយប្រើ HTTP Module

1. Definition (និយមន័យ):

HTTP Module គឺជា Built-in Module របស់ Node.js ដែលប្រើសម្រាប់បង្កើត Web Server ដើម្បីទទួលសំណើ (Request) ពីអ្នកប្រើប្រាស់ និងបញ្ជូនទិន្នន័យត្រឡប់ទៅវិញ (Response)។

2. មុខងារ និង Methods សំខាន់ៗ:

  • http.createServer((req, res) => {}) (បង្កើត Server)៖ បង្កើតកម្មវិធី Server សម្រាប់ទទួលសំណើ និងឆ្លើយតប។
  • res.writeHead(200, {...}) (កំណត់ Header)៖ កំណត់លេខកូដស្ថានភាព (200 = ជោគជ័យ) និងប្រភេទទិន្នន័យ (Content-Type)។
  • res.end(data) (បញ្ចប់ការឆ្លើយតប)៖ បញ្ជូនទិន្នន័យចុងក្រោយទៅកាន់ Client និងបិទការតភ្ជាប់នៃសំណើនោះ។
  • server.listen(3000) (បើកដំណើរការ Port)៖ កំណត់លេខ Port (ឧ. 3000) ដើម្បីឱ្យ Server រង់ចាំទទួលសំណើ។

Parameters ស្នូលទាំង ២ ក្នុង Server៖

  • req (Request Object)៖ ផ្ទុកព័ត៌មានសំណើដែលផ្ញើមកពីអ្នកប្រើប្រាស់ (URL, Method, Headers)។
  • res (Response Object)៖ ប្រើសម្រាប់រៀបចំ និងបញ្ជូនទិន្នន័យត្រឡប់ទៅអ្នកប្រើប្រាស់វិញ។

3. Syntax (ទម្រង់កូដ):

const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ message: "សួស្តីពី Node.js HTTP Server!" }));
});

server.listen(3000, () => {
  console.log("Server កំពុងដំណើរការនៅ http://localhost:3000");
});

4. Output (លទ្ធផលនៅលើ Terminal & Browser):

Terminal & Response
$ node server.js
Server កំពុងដំណើរការនៅ http://localhost:3000
Response: {"message":"សួស្តីពី Node.js HTTP Server!"}
5. Summary (សង្ខេបមេរៀន)៖ ការប្រើ http សុទ្ធអាចបង្កើត Server បាន ប៉ុន្តែពេលមាន Routes ច្រើនវានឹងស្មុគស្មាញ ទើបគេប្រើ Express.js មកជំនួស។

Node.js & Express.js 6. Introduction to Express.js

6. សេចក្តីផ្តើមអំពី Express.js & ការរៀបចំ Structure គម្រោង

1. Definition (និយមន័យ):

Express.js គឺជា Web Application Framework ដ៏ពេញនិយមបំផុតរបស់ Node.js ដែលជួយឱ្យការបង្កើត Server, ការគ្រប់គ្រង Routing និងការសរសេរ REST API មានភាពងាយស្រួល ខ្លី និងមានរបៀបរៀបរយ។

2. មុខងារ និងសមាសធាតុសំខាន់ៗ:

  • const app = express() (បង្កើត App)៖ ចាប់ផ្តើមបង្កើត Instance របស់ Express ដើម្បីកំណត់ Routes និង Middleware។
  • res.json(data) (ឆ្លើយតប JSON)៖ បំប្លែង JavaScript Object ទៅជាទម្រង់ JSON ដោយស្វ័យប្រវត្តិ (ងាយជាង http សុទ្ធ)។
  • app.listen(PORT) (បើក Server)៖ ចាប់ផ្តើមដំណើរការ Express Server លើ Port ដែលកំណត់។

រចនាសម្ព័ន្ធ Folder ស្តង់ដារក្នុង Express៖

  • routes/ & controllers/ ៖ បំបែកផ្លូវ URL និង Functions ដោះស្រាយកូដតាមមុខងារ។
  • models/ & config/ ៖ ផ្ទុក Schema ទិន្នន័យ និងការកំណត់តភ្ជាប់ Database។
  • server.js (Entry Point)៖ ឯកសារមេសម្រាប់ដំណើរការកម្មវិធីទាំងមូល។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលបង្កើត Backend REST API សម្រាប់គេហទំព័រ (React, Next.js) ឬ Mobile App ជំនួសឱ្យការប្រើ http module សុទ្ធរបស់ Node.js។

4. Syntax (ទម្រង់កូដបង្កើត Server ជាមួយ Express.js):

const express = require('express');
const app = express();
const PORT = 5000;

app.get('/', (req, res) => {
  res.json({ status: "success", message: "ស្វាគមន៍មកកាន់ Express API!" });
});

app.listen(PORT, () => console.log(`Server running on port ${PORT}`));

5. Output (លទ្ធផលនៅលើ Terminal & Postman):

GET http://localhost:5000/
Server running on port 5000
{"status": "success", "message": "ស្វាគមន៍មកកាន់ Express API!"}
6. Summary (សង្ខេបមេរៀន)៖ Express.js កាត់បន្ថយកូដស្មុគស្មាញរបស់ Node.js ដោយផ្តល់នូវ app.get() និង res.json() សម្រាប់បង្កើត API បានយ៉ាងរហ័ស។

Node.js & Express.js 7. Routing & HTTP Methods

7. ការគ្រប់គ្រង Routing & HTTP Methods

1. Definition (និយមន័យ):

Routing គឺជាការកំណត់ផ្លូវ (URL Endpoints) និងវិធីសាស្ត្រស្នើសុំ (HTTP Methods) ដើម្បីឱ្យ Server ដឹងថាត្រូវឆ្លើយតបបែបណានៅពេលអ្នកប្រើប្រាស់ចូលទៅកាន់ URL ណាមួយ។

2. មុខងារ និង HTTP Methods សំខាន់ៗ:

  • app.METHOD(path, handler) (ទម្រង់ Route)៖ កំណត់ HTTP Method ផ្លូវ URL និង Function សម្រាប់ឆ្លើយតប។
  • :id (Dynamic Route Parameter)៖ កំណត់ទីតាំង ID ប្រែប្រួលនៅក្នុងផ្លូវ URL (ឧ. /api/courses/:id)។

HTTP Methods ទាំង ៤ របស់ REST API (CRUD)៖

  • app.get() (GET - Read)៖ ប្រើសម្រាប់អាន ឬទាញបញ្ជីទិន្នន័យពី Server។
  • app.post() (POST - Create)៖ ប្រើសម្រាប់បញ្ជូនទិន្នន័យថ្មីទៅរក្សាទុកក្នុង Server។
  • app.put() (PUT - Update)៖ ប្រើសម្រាប់កែប្រែព័ត៌មានដែលមានស្រាប់តាមរយៈ ID។
  • app.delete() (DELETE - Delete)៖ ប្រើសម្រាប់លុបទិន្នន័យចេញពីប្រព័ន្ធ។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលបង្កើត API Endpoints សម្រាប់ឱ្យ Frontend ធ្វើសកម្មភាពផ្សេងៗ ដូចជា ទាញបញ្ជីទំនិញ (GET), បន្ថែមទំនិញ (POST), កែតម្លៃ (PUT) ឬលុបទំនិញ (DELETE)។

4. Syntax (ទម្រង់កូដ):

app.get('/api/courses', (req, res) => {
  res.json([{ id: 1, title: "HTML & CSS" }, { id: 2, title: "Node.js" }]);
});
app.post('/api/courses', (req, res) => {
  res.status(201).json({ message: "បង្កើតមុខវិជ្ជាថ្មីបានជោគជ័យ!" });
});
app.put('/api/courses/:id', (req, res) => res.json({ message: "កែប្រែជោគជ័យ!" }));
app.delete('/api/courses/:id', (req, res) => res.json({ message: "លុបជោគជ័យ!" }));

5. Output (លទ្ធផលនៅលើ Postman):

POST http://localhost:5000/api/courses — 201 Created
{"message": "បង្កើតមុខវិជ្ជាថ្មីបានជោគជ័យ!"}
6. Summary (សង្ខេបមេរៀន)៖ ការរចនា REST API ត្រូវប្រើ Method ឱ្យត្រូវតាមមុខងារ៖ GET (អាន), POST (បង្កើត), PUT (កែប្រែ) និង DELETE (លុប)។

Node.js & Express.js 8. Request Data (Params, Query, Body)

8. ការចាប់ទិន្នន័យពី Request (req.params, req.query, req.body)

1. Definition (និយមន័យ):

នៅពេល Frontend ឬ Postman ផ្ញើសំណើមកកាន់ Server ទិន្នន័យទាំងអស់ត្រូវបានផ្ទុកនៅក្នុង Object req (Request) ដែលយើងអាចទាញយកតាម ៣ របៀបសំខាន់ៗ។

2. មុខងារ និងវិធីចាប់ទិន្នន័យសំខាន់ៗ:

  • app.use(express.json()) (JSON Parser)៖ ចាំបាច់ត្រូវបើកជាមុន ដើម្បីឱ្យ Express អាចអានទិន្នន័យក្នុង req.body បាន។
  • Object Destructuring៖ ទាញយក Properties ចេញពី req.body យ៉ាងខ្លី (ឧ. const { name, email } = req.body)។

ប្រភពទិន្នន័យទាំង ៣ ក្នុង Request Object៖

  • req.params (Route Parameters)៖ ចាប់តម្លៃដែលភ្ជាប់ក្នុងផ្លូវ URL ផ្ទាល់ (ឧ. /users/:id ➔ req.params.id)។
  • req.query (Query Strings)៖ ចាប់តម្លៃស្វែងរកនៅខាងក្រោយសញ្ញា ? (ឧ. /search?role=admin ➔ req.query.role)។
  • req.body (Request Body)៖ ចាប់ទិន្នន័យ JSON ដែលផ្ញើតាម POST ឬ PUT។

3. ប្រើពេលណា (When to Use):

ប្រើ params ពេលចង់មើល ឬលុបទិន្នន័យតាម ID ជាក់លាក់, ប្រើ query ពេលធ្វើមុខងារ Search/Filter និងប្រើ body ពេលទទួលទិន្នន័យចុះឈ្មោះ ឬបង្កើតថ្មី។

4. Syntax (ទម្រង់កូដ):

app.use(express.json()); // ចាំបាច់សម្រាប់អាន req.body

app.get('/api/users/:id', (req, res) => {
  res.json({ userId: req.params.id, keyword: req.query.role });
});

app.post('/api/users', (req, res) => {
  const { name, email } = req.body;
  res.json({ received: { name, email } });
});

5. Output (លទ្ធផលនៅលើ Postman):

GET http://localhost:5000/api/users/101?role=admin
{"userId": "101", "keyword": "admin"}
6. Summary (សង្ខេបមេរៀន)៖ ប្រើ req.params សម្រាប់ចាប់ ID, ប្រើ req.query សម្រាប់ Filter/Search និងប្រើ req.body សម្រាប់ទទួលទិន្នន័យ Form ឬ JSON។

Node.js & Express.js 9. Middleware in Express.js

9. ការប្រើប្រាស់ Middleware (express.json, Custom, CORS)

1. Definition (និយមន័យ):

Middleware គឺជា Function កណ្តាលដែលដំណើរការនៅចន្លោះពេល Server ទទួលបាន Request និងមុនពេលបញ្ជូន Response ត្រឡប់ទៅវិញ (ដូចជាអ្នកត្រួតពិនិត្យសំបុត្រមុនចូលរោងកុន)។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • app.use(middleware) (បើកប្រើ Middleware)៖ កំណត់ឱ្យ Middleware ដំណើរការលើគ្រប់ Requests ទាំងអស់។
  • next() (បន្តដំណើរការ)៖ ជា Function សម្រាប់ប្រាប់ Express ឱ្យបន្តទៅកាន់ Route ឬ Middleware បន្ទាប់ (បើភ្លេចហៅ កម្មវិធីនឹងគាំង)។

ប្រភេទ Middleware ទាំង ៣ ក្នុង Express.js៖

  • Built-in Middleware៖ ភ្ជាប់មកស្រាប់ក្នុង Express (ឧ. express.json() សម្រាប់អានទិន្នន័យ JSON)។
  • Third-party Middleware៖ ដំឡើងបន្ថែមតាម NPM (ឧ. cors() ដើម្បីអនុញ្ញាតឱ្យ Frontend ភ្ជាប់មក API)។
  • Custom Middleware៖ សរសេរដោយខ្លួនឯង (req, res, next) => {} សម្រាប់ពិនិត្យ Token (Auth) ឬ Log។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលត្រូវការបើកសិទ្ធិ CORS ឱ្យ Frontend ភ្ជាប់មក, អាន JSON Body, ពិនិត្យ Token សុវត្ថិភាព (Authentication) ឬកត់ត្រាប្រវត្តិ Requests។

4. Syntax (ទម្រង់កូដបង្កើត Custom Middleware):

const cors = require('cors');
app.use(cors());
app.use(express.json());

const logger = (req, res, next) => {
  console.log(`[${new Date().toLocaleTimeString()}] ${req.method} ${req.url}`);
  next(); // បើភ្លេចហៅ next() នោះ Request នឹងគាំងត្រឹមនេះ!
};
app.use(logger);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — Middleware Log
[10:15:30 AM] GET /api/courses
[10:15:42 AM] POST /api/users
6. Summary (សង្ខេបមេរៀន)៖ Middleware ប្រើតាមរយៈ app.use() សម្រាប់ពិនិត្យសិទ្ធិ (Auth), អនុញ្ញាត cors() និងអាន JSON ហើយត្រូវហៅ next() ជានិច្ច។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 11
Node.js & Express.js 10. MVC Pattern (Routes & Controllers)

10. ការរៀបចំកូដតាមគំរូ MVC (Routes & Controllers)

1. Definition (និយមន័យ):

MVC (Model - View - Controller) គឺជាគំរូរៀបចំរចនាសម្ព័ន្ធកូដ Backend ដោយបំបែកផ្នែកកំណត់ផ្លូវ (Routes) ផ្នែកដោះស្រាយតក្កវិជ្ជា (Controllers) និងផ្នែកទិន្នន័យ (Models) ដាច់ពីគ្នា។

2. មុខងារ និងសមាសធាតុសំខាន់ៗ:

  • express.Router() (បង្កើត Route)៖ ជួយបំបែកផ្លូវ API តាមក្រុមមុខងារ (ឧ. userRoutes.js, productRoutes.js)។
  • app.use('/api/products', router) (ភ្ជាប់ Route)៖ កំណត់ Prefix URL រួមសម្រាប់ភ្ជាប់ Route ចូលក្នុង server.js។

តួនាទីសំខាន់ៗក្នុង MVC Architecture៖

  • Model៖ គ្រប់គ្រងរចនាសម្ព័ន្ធទិន្នន័យ និងការតភ្ជាប់ជាមួយ Database (Mongoose Schema)។
  • Controller៖ ផ្ទុក Functions សម្រាប់ដំណើរការតក្កវិជ្ជា និងរៀបចំទិន្នន័យឆ្លើយតបទៅ Client។
  • Route (ជំនួស View ក្នុង REST API)៖ កំណត់ URL Endpoints ហើយបញ្ជូនសំណើទៅកាន់ Controller។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលគម្រោង API ចាប់ផ្តើមមាន Endpoints ច្រើន (ដូចជា Users, Products, Orders) ដើម្បីកុំឱ្យកូដទាំងអស់គរនៅក្នុង server.js តែមួយ។

4. Syntax (ទម្រង់កូដបំបែក Controller និង Route):

// ១. controllers/productController.js
const getProducts = (req, res) => res.json([{ id: 1, name: "Laptop Dell" }]);
module.exports = { getProducts };

// ២. routes/productRoutes.js
const router = require('express').Router();
const { getProducts } = require('../controllers/productController');
router.get('/', getProducts);
module.exports = router;

5. Output (ការភ្ជាប់ក្នុង server.js និងលទ្ធផល):

GET http://localhost:5000/api/products
// server.js: app.use('/api/products', require('./routes/productRoutes'));
[{"id": 1, "name": "Laptop Dell"}]
6. Summary (សង្ខេបមេរៀន)៖ ការប្រើ express.Router() និងបំបែក Controllers ធ្វើឱ្យគម្រោងធំៗងាយស្រួលថែទាំ និងធ្វើការងារជាក្រុមបានរលូន។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 12
Node.js & Express.js 11. Environment Variables (.env)

11. ការគ្រប់គ្រងអថេរសម្ងាត់ជាមួយ Environment Variables (.env)

1. Definition (និយមន័យ):

Environment Variables (.env) គឺជាឯកសារពិសេសសម្រាប់រក្សាទុកព័ត៌មានសម្ងាត់ និងការកំណត់ប្រព័ន្ធ ដូចជាលេខ Port, Database URL, និង API Keys ដោយមិនសរសេរចូលក្នុងកូដផ្ទាល់។

2. មុខងារ និងពាក្យបញ្ជាសំខាន់ៗ:

  • npm install dotenv (ដំឡើង)៖ ដំឡើងកញ្ចប់ dotenv សម្រាប់អានទិន្នន័យពីឯកសារ .env។
  • require('dotenv').config() (បើកដំណើរការ)៖ ត្រូវសរសេរនៅបន្ទាត់លើគេបង្អស់នៃឯកសារ server.js។
  • process.env.KEY_NAME (ហៅតម្លៃមកប្រើ)៖ ទាញយកតម្លៃអថេរពី .env មកប្រើប្រាស់ក្នុងកូដ។

គោលការណ៍សុវត្ថិភាពសំខាន់ៗ៖

  • ការពារលើ GitHub (.gitignore)៖ ត្រូវបន្ថែម .env ចូលក្នុង .gitignore ជានិច្ច ដើម្បីកុំឱ្យបែកធ្លាយពាក្យសម្ងាត់។
  • Fallback Value (||)៖ កំណត់តម្លៃបម្រុងទុក (ឧ. process.env.PORT || 3000) ការពារពេលរកមិនឃើញ .env។

3. ប្រើពេលណា (When to Use):

ប្រើរាល់ពេលភ្ជាប់ Database, រក្សាទុក JWT Secret Key ឬមុនពេល Push កូដគម្រោងទៅកាន់ GitHub ដើម្បីការពារសុវត្ថិភាពទិន្នន័យ។

4. Syntax (ទម្រង់ឯកសារ .env និង server.js):

# ១. ឯកសារ .env
PORT=5000
MONGO_URI=mongodb://localhost:27017/school_db

// ២. ឯកសារ server.js
require('dotenv').config();
const port = process.env.PORT || 3000;
console.log("Port ពី .env គឺ៖", port);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node server.js
Port ពី .env គឺ៖ 5000
6. Summary (សង្ខេបមេរៀន)៖ រាល់ព័ត៌មានសម្ងាត់ដូចជា Password Database ឬ Secret Key ត្រូវទុកក្នុង .env ហើយហៅប្រើតាម process.env ជានិច្ច។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 13
Node.js & Express.js 12. Connecting MongoDB with Mongoose

12. ការតភ្ជាប់ Express.js ទៅកាន់ MongoDB (Mongoose)

1. Definition (និយមន័យ):

Mongoose គឺជា ODM (Object Data Modeling) Library សម្រាប់តភ្ជាប់ Node.js/Express.js ទៅកាន់ MongoDB និងជួយកំណត់រចនាសម្ព័ន្ធទិន្នន័យ (Schema) ឱ្យមានស្តង់ដារច្បាស់លាស់។

2. មុខងារ និង Methods សំខាន់ៗ:

  • mongoose.connect(uri) (តភ្ជាប់ Database)៖ ភ្ជាប់ Server ទៅកាន់ MongoDB Compass (Local) ឬ MongoDB Atlas (Cloud)។
  • new mongoose.Schema({...}) (បង្កើតគំរូទិន្នន័យ)៖ កំណត់ឈ្មោះ Fields, ប្រភេទទិន្នន័យ (String, Number, Boolean) និងលក្ខខណ្ឌ (required)។
  • mongoose.model('Name', schema) (បង្កើត Model)៖ បង្កើត Collection ក្នុង Database ដើម្បីយកទៅប្រើសម្រាប់ប្រតិបត្តិការ CRUD។

ជម្រើសបន្ថែមក្នុង Schema (Schema Options)៖

  • { timestamps: true } ៖ បន្ថែម createdAt និង updatedAt ដោយស្វ័យប្រវត្តិរាល់ពេលបង្កើត ឬកែប្រែទិន្នន័យ។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលត្រូវការរក្សាទុកទិន្នន័យជាអចិន្ត្រៃយ៍ (Persistent Storage) ក្នុង MongoDB ជំនួសឱ្យការទុកទិន្នន័យបណ្តោះអាសន្នក្នុង Array នៃកូដ។

4. Syntax (ទម្រង់កូដតភ្ជាប់ និងបង្កើត Model):

const mongoose = require('mongoose');

mongoose.connect(process.env.MONGO_URI)
  .then(() => console.log("តភ្ជាប់ MongoDB បានជោគជ័យ!"))
  .catch(err => console.error("បរាជ័យ៖", err));

const studentSchema = new mongoose.Schema({
  name: { type: String, required: true },
  age: Number,
  course: String
}, { timestamps: true });

const Student = mongoose.model('Student', studentSchema);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — Database Connection
Server running on port 5000
តភ្ជាប់ MongoDB បានជោគជ័យ!
6. Summary (សង្ខេបមេរៀន)៖ ដំឡើង npm install mongoose រួចប្រើ mongoose.connect() ដើម្បីភ្ជាប់ Database និងបង្កើត Schema សម្រាប់គ្រប់គ្រងទិន្នន័យ។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 14
Node.js & Express.js 13. Full CRUD API Operations

13. ការបង្កើត CRUD API ពេញលេញ (Create, Read, Update, Delete)

1. Definition (និយមន័យ):

CRUD មកពីពាក្យ Create (បង្កើត), Read (អាន), Update (កែប្រែ) និង Delete (លុប) ដែលជាប្រតិបត្តិការស្នូលទាំង ៤ របស់ Backend API ជាមួយ Database ដោយប្រើ async / await។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • async / await (Asynchronous)៖ ប្រើសម្រាប់រង់ចាំឱ្យ Database ដំណើរការចប់សព្វគ្រប់ មុននឹងបន្តទៅបន្ទាត់កូដបន្ទាប់។
  • { new: true } (Return Updated Data)៖ កំណត់ឱ្យ Mongoose ត្រឡប់ទិន្នន័យថ្មីដែលទើបកែប្រែរួចមកវិញ។

Mongoose CRUD Methods ទាំង ៤ ប្រភេទ៖

  • C - Create៖ Model.create(req.body) បង្កើត និងរក្សាទុកទិន្នន័យថ្មីចូល MongoDB។
  • R - Read៖ Model.find() ទាញបញ្ជីទិន្នន័យទាំងអស់ (ឬ Model.findById(id) សម្រាប់ទិន្នន័យមួយ)។
  • U - Update៖ Model.findByIdAndUpdate(id, req.body, { new: true }) កែប្រែទិន្នន័យតាម ID។
  • D - Delete៖ Model.findByIdAndDelete(id) លុបទិន្នន័យចេញពី Database តាម ID។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលបង្កើតមុខងារគ្រប់គ្រងទិន្នន័យពេញលេញក្នុងប្រព័ន្ធ ដូចជា ប្រព័ន្ធគ្រប់គ្រងសិស្ស គ្រប់គ្រងស្តុកទំនិញ ឬប្រព័ន្ធបង្ហោះអត្ថបទ។

4. Syntax (ទម្រង់កូដ Controller ពេញលេញ):

app.post('/api/students', async (req, res) => {
  const student = await Student.create(req.body);
  res.status(201).json(student);
});
app.get('/api/students', async (req, res) => {
  res.json(await Student.find());
});
app.put('/api/students/:id', async (req, res) => {
  res.json(await Student.findByIdAndUpdate(req.params.id, req.body, { new: true }));
});
app.delete('/api/students/:id', async (req, res) => {
  await Student.findByIdAndDelete(req.params.id);
  res.json({ message: "លុបទិន្នន័យសិស្សរួចរាល់!" });
});

5. Output (លទ្ធផលនៅលើ Postman):

POST http://localhost:5000/api/students — 201 Created
{"_id": "673a91f8b2c4e", "name": "ចាន់ ដារ៉ា", "age": 20, "course": "Web Dev"}
6. Summary (សង្ខេបមេរៀន)៖ ប្រើ async / await រួមជាមួយ .create(), .find(), .findByIdAndUpdate() និង .findByIdAndDelete() ដើម្បីគ្រប់គ្រងទិន្នន័យ CRUD ទាំងស្រុង។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 15
Node.js & Express.js 14. Error Handling & HTTP Status Codes

14. ការគ្រប់គ្រង Error Handling និង HTTP Status Codes

1. Definition (និយមន័យ):

Error Handling គឺជាការចាប់កំហុសដែលកើតឡើងក្នុងពេលដំណើរការ Server (ដូចជា ID ខុសទម្រង់ ឬ Database ដាច់) ដើម្បីកុំឱ្យ Server គាំង (Crash) និងបញ្ជូនសារប្រាប់អ្នកប្រើប្រាស់វិញឱ្យបានត្រឹមត្រូវ។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • try { ... } catch (error) { ... } (ចាប់កំហុស)៖ ស្រោបកូដ async / await ដើម្បីចាប់យកកំហុសមកដោះស្រាយដោយសុវត្ថិភាព។
  • res.status(code).json(...) (បញ្ជូន Status Code)៖ កំណត់លេខកូដស្ថានភាព HTTP ភ្ជាប់ជាមួយសារ JSON ត្រឡប់ទៅ Client។

HTTP Status Codes ស្តង់ដារទាំង ៤ ក្រុម៖

  • 200 OK / 201 Created (ជោគជ័យ)៖ 200 ដំណើរការជោគជ័យ និង 201 បង្កើតទិន្នន័យថ្មីជោគជ័យ។
  • 400 Bad Request (ទិន្នន័យខុស)៖ អ្នកប្រើប្រាស់បញ្ចូលទិន្នន័យខ្វះ ឬខុសលក្ខខណ្ឌ។
  • 404 Not Found (រកមិនឃើញ)៖ ផ្លូវ URL ឬ ID ទិន្នន័យដែលស្វែងរកមិនមានក្នុងប្រព័ន្ធ។
  • 500 Internal Server Error (កំហុស Server)៖ កំហុសបច្ចេកទេសខាង Server ឬ Database ដាច់ការតភ្ជាប់។

3. ប្រើពេលណា (When to Use):

ប្រើគ្រប់ពេលសរសេរកូដ async / await ជាមួយ Database ដើម្បីការពារកុំឱ្យ Server រលត់ពេលមានបញ្ហា និងជួយឱ្យ Frontend ដឹងពីមូលហេតុនៃកំហុសច្បាស់លាស់។

4. Syntax (ទម្រង់កូដ try...catch):

app.get('/api/students/:id', async (req, res) => {
  try {
    const student = await Student.findById(req.params.id);
    if (!student) return res.status(404).json({ message: "រកមិនឃើញទិន្នន័យសិស្សនេះទេ!" });
    res.status(200).json(student);
  } catch (error) {
    res.status(500).json({ message: "មានបញ្ហា Server៖", error: error.message });
  }
});

5. Output (លទ្ធផលនៅលើ Postman ពេលរកមិនឃើញ ID):

GET http://localhost:5000/api/students/673a999999999 — 404 Not Found
{"message": "រកមិនឃើញទិន្នន័យសិស្សនេះទេ!"}
6. Summary (សង្ខេបមេរៀន)៖ រាល់កូដដែលប្រើ async / await ត្រូវតែស្រោបដោយ try...catch ជានិច្ច និងប្រើ res.status() ឱ្យត្រូវតាមស្ថានភាពជាក់ស្តែង។
