Node.js & Express.js 1. Introduction to Node.js

1. សេចក្តីផ្តើមអំពី Node.js & ការដំឡើង

1. Definition (និយមន័យ):

Node.js គឺជា JavaScript Runtime Environment ដែលអនុញ្ញាតឱ្យយើងអាចដំណើរការកូដ (Run) JavaScript នៅខាងក្រៅ Browser (នៅលើ Server ឬកុំព្យូទ័រផ្ទាល់) បាន ដោយប្រើប្រាស់ V8 Engine របស់ Google Chrome។

2. មុខងារ និងពាក្យបញ្ជាសំខាន់ៗ:

  • node -v (ពិនិត្យជំនាន់)៖ ពាក្យបញ្ជាសម្រាប់ឆែកមើលជំនាន់ Node.js ដែលបានដំឡើងលើម៉ាស៊ីន។
  • node app.js (ដំណើរការកូដ)៖ ប្រើសម្រាប់ Run ឯកសារ JavaScript (.js) នៅក្នុង Terminal។
  • node --watch app.js (Auto Restart)៖ Run ឯកសារ .js ដោយដំណើរការឡើងវិញស្វ័យប្រវត្តិរាល់ពេលកែប្រែកូដ។

លក្ខណៈពិសេសស្នូលរបស់ Node.js:

  • V8 Engine៖ បម្លែងកូដ JavaScript ទៅជា Machine Code បានយ៉ាងលឿនបំផុត។
  • Non-blocking I/O (Input/Output)៖ អាចទទួលសំណើ (Requests) ពីអ្នកប្រើប្រាស់ច្រើននាក់ព្រមគ្នាដោយមិនរង់ចាំគ្នា។
  • Full-Stack JavaScript៖ ប្រើភាសា JavaScript តែមួយទាំងផ្នែក Frontend និង Backend។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលយើងចង់បង្កើត Server-Side Web Application, RESTful APIs, Real-time Chat Apps ឬប្រព័ន្ធគ្រប់គ្រងទិន្នន័យដែលត្រូវការល្បឿនលឿន។

4. Syntax (ទម្រង់កូដបង្កើត File ដំបូង - app.js):

// បង្កើតឯកសារឈ្មោះ app.js
const studentName = "សុខា";
const course = "Node.js & Express.js";

console.log(`សួស្តី ${studentName}! ស្វាគមន៍មកកាន់មេរៀន ${course}`);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node -v
v22.11.0
$ node app.js
សួស្តី សុខា! ស្វាគមន៍មកកាន់មេរៀន Node.js & Express.js
6. Summary (សង្ខេបមេរៀន)៖ Node.js គឺជា JavaScript Runtime Environment ដែលប្រើ V8 Engine ដើម្បីដំណើរការកូដ JavaScript នៅខាងក្រៅ Browser (លើ Server) តាមរយៈពាក្យបញ្ជា node ឈ្មោះឯកសារ.js។

Node.js & Express.js 2. NPM & Package Management

2. ការគ្រប់គ្រងគម្រោងជាមួយ NPM (package.json)

1. Definition (និយមន័យ):

NPM (Node Package Manager) គឺជាកម្មវិធីគ្រប់គ្រងកញ្ចប់កូដ (Libraries/Packages) របស់ Node.js ដែលភ្ជាប់មកជាមួយស្រាប់ពេលយើងដំឡើង Node.js។

2. មុខងារ និងពាក្យបញ្ជាសំខាន់ៗ:

  • npm init -y (បង្កើតគម្រោងថ្មី)៖ បង្កើតឯកសារ package.json ដោយស្វ័យប្រវត្តិសម្រាប់កត់ត្រាព័ត៌មានគម្រោង។
  • package.json (កន្លែងកត់ត្រា)៖ ជាកន្លែងកត់ត្រាឈ្មោះ Packages, Scripts និងបញ្ជី Libraries ដែលបានដំឡើង។
  • node_modules/ (ថតផ្ទុកកញ្ចប់កូដ)៖ ថតផ្ទុកកូដ Libraries ទាំងអស់ដែលបានទាញយកមកប្រើ។
  • .gitignore (ឯកសារមិនរាប់បញ្ចូលក្នុង Git)៖ ឯកសារសម្រាប់ហាមមិនឱ្យ Upload node_modules/ និង .env ទៅកាន់ GitHub។

ភាពខុសគ្នារវាង Dependencies vs DevDependencies៖

  • Dependencies (npm install <pkg>)៖ កញ្ចប់កូដស្នូលដែលកម្មវិធីត្រូវការជាចាំបាច់ទាំងពេលសរសេរកូដ និងពេលបង្ហោះលើ Server ពិត (Production) ដូចជា express, mongoose។
  • DevDependencies (npm install -D <pkg>)៖ ឧបករណ៍ជំនួយសម្រាប់ប្រើតែពេលសរសេរកូដ (Development) ប៉ុណ្ណោះ មិនយកទៅប្រើលើ Server ពិតទេ ដូចជា nodemon។

3. Syntax (ទម្រង់ឯកសារ package.json):

{
  "name": "my-backend-api",
  "version": "1.0.0",
  "main": "server.js",
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  },
  "dependencies": {
    "express": "^4.21.1"
  },
  "devDependencies": {
    "nodemon": "^3.1.7"
  }
}

4. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ npm init -y
Wrote to /my-backend-api/package.json
$ npm install express && npm install -D nodemon
added 96 packages in 3s
5. Summary (សង្ខេបមេរៀន)៖ NPM ប្រើសម្រាប់គ្រប់គ្រង Libraries តាមរយៈ package.json ដោយប្រើ npm install សម្រាប់ Dependencies (Production) និង npm install -D សម្រាប់ DevDependencies (Development)។

Node.js & Express.js 3. Node.js Module System

3. Modules ក្នុង Node.js (CommonJS vs ES Modules)

1. Definition (និយមន័យ):

Module គឺជាការបំបែកកូដ JavaScript ជាឯកសារតូចៗដាច់ដោយឡែកពីគ្នាតាមមុខងារ ដើម្បីងាយស្រួលគ្រប់គ្រង និង កែប្រែ។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • module.exports (បញ្ចេញកូដ)៖ ប្រើសម្រាប់បញ្ជូន Functions ឬ Variables ចេញពីឯកសារបច្ចុប្បន្ន។
  • require('./file') (ទាញកូដមកប្រើ)៖ ប្រើសម្រាប់នាំចូល Module ពីឯកសារផ្សេងមកប្រើ (ត្រូវដាក់ ./ សម្រាប់ឯកសារបង្កើតខ្លួនឯង)។

ប្រព័ន្ធ Modules ទាំង ២ ក្នុង Node.js:

  • CommonJS (Default)៖ ប្រើ module.exports និង require() (ទម្រង់ដើមរបស់ Node.js)។
  • ES Modules (ES6)៖ ប្រើ export និង import (ត្រូវថែម "type": "module" ក្នុង package.json)។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលគម្រោងមាន កូដ ច្រើន ហើយយើងចង់បំបែកជាផ្នែកៗ (ដូចជា Database Config, Routes, Controllers) ដើម្បីឱ្យមានរបៀបរៀបរយ។

4. Syntax (ទម្រង់កូដ CommonJS):

// ១. ឯកសារ math.js (បញ្ចេញ Function)
const add = (a, b) => a + b;
const multiply = (a, b) => a * b;
module.exports = { add, multiply };

// ២. ឯកសារ app.js (ទាញយកមកប្រើ)
const { add, multiply } = require('./math');
console.log("ផលបូក៖", add(10, 5));
console.log("ផលគុណ៖", multiply(10, 5));

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node app.js
ផលបូក៖ 15
ផលគុណ៖ 50
6. Summary (សង្ខេបមេរៀន)៖ Module គឺជាការបំបែកកូដជាឯកសារតូចៗដើម្បីងាយស្រួលគ្រប់គ្រង និងកែប្រែ ដោយប្រើ module.exports និង require('./file') (CommonJS) ឬ export និង import (ES Modules)។

Node.js & Express.js 4. Path Module

4. ការគ្រប់គ្រងទីតាំង File និង Folder ជាមួយ Path Module

1. Definition (និយមន័យ):

Path Module គឺជា Built-in Module របស់ Node.js ដែលប្រើសម្រាប់គ្រប់គ្រងទីតាំងឯកសារ File និង Folder។

2. មុខងារ និងពាក្យបញ្ជាសំខាន់ៗ:

  • __dirname (ទីតាំង Folder បច្ចុប្បន្ន)៖ បង្ហាញទីតាំងពេញ (Absolute Path) នៃ Folder ដែលឯកសារកំពុងដំណើរការ។
  • __filename (ទីតាំង File បច្ចុប្បន្ន)៖ បង្ហាញទីតាំងពេញរួមទាំងឈ្មោះ File ដែលកំពុងដំណើរការ។
  • path.join() (តភ្ជាប់ទីតាំង)៖ ភ្ជាប់ឈ្មោះ Folder និង File ចូលគ្នាដោយប្រើសញ្ញា / ឬ \ ត្រឹមត្រូវតាម OS ស្វ័យប្រវត្តិ។
  • path.resolve() (បង្កើតទីតាំងពេញ)៖ បំប្លែងទីតាំងឯកសារទៅជាទីតាំងពេញលេញចាប់ពីឫស (Root)។
  • path.basename() (ទាញយកឈ្មោះ File)៖ កាត់យកតែឈ្មោះ File ចុងក្រោយចេញពីទីតាំងពេញ (ឧ. index.html)។
  • path.extname() (ទាញយកកន្ទុយ File)៖ ពិនិត្យមើលប្រភេទកន្ទុយ File (ឧ. .js, .png, .pdf)។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលយើងចង់អាន/សរសេរ File (ជាមួយ fs), កំណត់ទីតាំងរក្សាទុករូបភាព Upload ឬបញ្ជូនឯកសារ Static (HTML/CSS) ទៅកាន់អ្នកប្រើប្រាស់។

4. Syntax (ទម្រង់កូដ):

const path = require('path');

// ភ្ជាប់ទីតាំងទៅកាន់ឯកសារ public/index.html
const fullPath = path.join(__dirname, 'public', 'index.html');

console.log('Full Path:', fullPath);
console.log('File Name:', path.basename(fullPath));
console.log('Extension:', path.extname(fullPath));

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node app.js
Full Path: /my-backend-api/public/index.html
File Name: index.html
Extension: .html
6. Summary (សង្ខេបមេរៀន)៖ Path Module ប្រើសម្រាប់គ្រប់គ្រងទីតាំង File/Folder ឱ្យដើរត្រូវគ្រប់ OS ដោយប្រើ path.join(__dirname, ...) ជំនួសការសរសេរទីតាំងដោយដៃ ដើម្បីការពារ Error ពេលប្តូរម៉ាស៊ីន ឬ Upload ទៅ Server។

Node.js & Express.js 5. Synchronous vs Asynchronous

5. Synchronous vs Asynchronous

1. Definition (និយមន័យ):

ក្នុង Node.js ការដំណើរការកូដចែកចេញជា ២ របៀបគឺ Synchronous (Blocking) ដែលដំណើរការម្តងមួយជំហានតាមលំដាប់ និង Asynchronous (Non-blocking) ដែលអាចដំណើរការកិច្ចការច្រើនព្រមគ្នាដោយមិនបាច់រង់ចាំកិច្ចការដែលប្រើពេលយូរចប់សិនឡើយ។

2. ភាពខុសគ្នាសំខាន់ៗ:

  • Synchronous (Blocking I/O)៖ កូដរត់ពីលើចុះក្រោមតាមលំដាប់។ បើជួរទី ២ ត្រូវការពេល ៥ វិនាទី ជួរទី ៣ ត្រូវរង់ចាំ ៥ វិនាទីដែរ (ធ្វើឱ្យ Server យឺត ឬគាំងពេលមានអ្នកប្រើច្រើន)។
  • Asynchronous (Non-blocking I/O)៖ កូដមិនរង់ចាំកិច្ចការយូរទេ (ដូចជាការទាញទិន្នន័យពី Database ឬអាន File ធំៗ) គឺវាបន្តទៅជួរបន្ទាប់ភ្លាម ហើយពេលកិច្ចការយូរនោះចប់ ទើបវាបង្ហាញលទ្ធផលតាមក្រោយ។

វិធីសរសេរ Asynchronous ទាំង ៣ ជំនាន់ក្នុង Node.js៖

  • Callback Function៖ បញ្ជូន Function ទៅរង់ចាំទទួលលទ្ធផលពេលកិច្ចការចប់។
  • Promises (.then() / .catch())៖ គ្រប់គ្រងលទ្ធផលជោគជ័យ ឬបរាជ័យឱ្យមានរបៀបជាង Callback។
  • Async / Await (ពេញនិយមបំផុត)៖ សរសេរកូដ Asynchronous ឱ្យមើលទៅសាមញ្ញដូច Synchronous តាមរយៈ async និង await។

3. ប្រើពេលណា (When to Use):

ប្រើ Asynchronous (async/await) ជានិច្ចនៅពេល Server ត្រូវធ្វើការជាមួយ Database, អាន/សរសេរ File ឬហៅទៅកាន់ API ខាងក្រៅ។

4. Syntax (ឧទាហរណ៍ប្រៀបធៀបការដំណើរការ):

// ឧទាហរណ៍ Asynchronous ដោយប្រើ setTimeout
console.log("១. ចាប់ផ្តើមទទួលការកុម្ម៉ង់...");

setTimeout(() => {
  console.log("២. ទាញទិន្នន័យពី Database រួចរាល់! (ប្រើពេល 2 វិនាទី)");
}, 2000);

console.log("៣. បន្តបម្រើភ្ញៀវបន្ទាប់ភ្លាមៗ (មិនរង់ចាំជួរទី ២)");

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node sync-async.js
១. ចាប់ផ្តើមទទួលការកុម្ម៉ង់...
៣. បន្តបម្រើភ្ញៀវបន្ទាប់ភ្លាមៗ (មិនរង់ចាំជួរទី ២)
២. ទាញទិន្នន័យពី Database រួចរាល់! (ប្រើពេល 2 វិនាទី)
6. Summary (សង្ខេបមេរៀន)៖ Synchronous រង់ចាំគ្នាតាមលំដាប់ (Blocking) ចំណែកឯ Asynchronous មិនរង់ចាំកិច្ចការយូរទេ (Non-blocking) ដែលជាចំណុចខ្លាំងធ្វើឱ្យ Node.js មានល្បឿនលឿន។

Node.js & Express.js 6. File System (fs) — Synchronous

6. ការគ្រប់គ្រង File & Folder ជាមួយ fs (Synchronous)

1. Definition (និយមន័យ):

FS (File System) Synchronous គឺជាវិធីគ្រប់គ្រងឯកសារ និង Folder ដោយដំណើរការតាមលំដាប់ពីលើចុះក្រោម (Blocking) ពោលគឺត្រូវរង់ចាំឱ្យកិច្ចការមួយចប់សិន ទើបបន្តទៅបន្ទាត់បន្ទាប់។

2. មុខងារ និង Methods សំខាន់ៗ (Sync):

  • fs.writeFileSync(file, data) (Create/Overwrite)៖ បង្កើត File ថ្មី ឬសរសេរជាន់ពីលើទិន្នន័យចាស់។
  • fs.readFileSync(file, 'utf8') (Read)៖ អានទិន្នន័យពី File (ដាក់ 'utf8' ដើម្បីបម្លែងពី Buffer ទៅជាអក្សរធម្មតា)។
  • fs.appendFileSync(file, data) (Update)៖ សរសេរទិន្នន័យបន្ថែមពីខាងចុង ដោយរក្សាទិន្នន័យចាស់ទុកដដែល។
  • fs.unlinkSync(file) (Delete File)៖ លុបឯកសារចេញពីប្រព័ន្ធ។

ការគ្រប់គ្រង Folder (Directory Operations)៖

  • fs.mkdirSync('folder') (Create Folder)៖ បង្កើត Folder ថ្មី (ប្រើ fs.existsSync() ឆែកជាមុន)។
  • fs.rmSync('folder', { recursive: true }) (Delete Folder)៖ លុប Folder និងឯកសារខាងក្នុងទាំងអស់។

3. ប្រើពេលណា (When to Use):

ប្រើសម្រាប់កិច្ចការតូចៗ ឬនៅពេលចាប់ផ្តើមបើក Server ដំបូង (ដូចជាការបង្កើត Folder uploads/ ទុកជាមុន) ដែលមិនប៉ះពាល់ដល់ល្បឿនអ្នកប្រើប្រាស់។

4. Syntax (ទម្រង់កូដ Sync):

const fs = require('fs');

if (!fs.existsSync('logs')) fs.mkdirSync('logs');          // 1. បង្កើត Folder
fs.writeFileSync('logs/app.txt', 'ជួរទី ១\n');            // 2. បង្កើត File
fs.appendFileSync('logs/app.txt', 'ជួរទី ២ (Update)');    // 3. កែបន្ថែមទិន្នន័យ
console.log(fs.readFileSync('logs/app.txt', 'utf8'));   // 4. អានទិន្នន័យ
fs.unlinkSync('logs/app.txt');                         // 5. លុប File
fs.rmSync('logs', { recursive: true });               // 6. លុប Folder

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — bash
$ node fs-sync.js
ជួរទី ១
ជួរទី ២ (Update)
6. Summary (សង្ខេបមេរៀន)៖ FS Synchronous គឺជាវិធីគ្រប់គ្រង File និង Folder តាមលំដាប់ពីលើចុះក្រោម (Blocking) ដោយប្រើ Methods ដែលមានពាក្យ Sync នៅខាងចុង ងាយស្រួលសរសេរសម្រាប់កិច្ចការតូចៗ ឬ Script ខ្លីៗ។

Node.js & Express.js 7. File System (fs) — Asynchronous

7. ការគ្រប់គ្រង File & Folder ជាមួយ fs (Asynchronous)

1. Definition (និយមន័យ):

FS (File System) Asynchronous គឺជាវិធីគ្រប់គ្រងឯកសារ និង Folder ដោយមិនរង់ចាំកិច្ចការចប់សិនឡើយ (Non-blocking) ពោលគឺអនុញ្ញាតឱ្យ Server បន្តដំណើរការកិច្ចការផ្សេងទៀតបានភ្លាមៗ តាមរយៈការប្រើ Callback ឬ Promises (async/await)។

2. មុខងារ និង Methods សំខាន់ៗ (Async Callback):

  • fs.writeFile(file, data, (err) => {}) (Create/Overwrite)៖ បង្កើត File ថ្មី ឬសរសេរជាន់ពីលើទិន្នន័យចាស់។
  • fs.readFile(file, 'utf8', (err, data) => {}) (Read)៖ អានទិន្នន័យពី File។
  • fs.appendFile(file, data, (err) => {}) (Update)៖ បន្ថែមទិន្នន័យពីខាងចុង ដោយរក្សាទិន្នន័យចាស់ទុកដដែល។
  • fs.unlink(file, (err) => {}) (Delete File)៖ លុបឯកសារចេញពីប្រព័ន្ធ។
  • fs.mkdir('folder', { recursive: true }, (err) => {}) (Create Folder)៖ បង្កើត Folder ថ្មី។
  • fs.rm('folder', { recursive: true }, (err) => {}) (Remove Folder)៖ លុប Folder ចេញពីប្រព័ន្ធ។

ចំណាំ៖ { recursive: true } ប្រើក្នុង mkdir ដើម្បីបង្កើត Folder ច្រើនជាន់ និងការពារ Error ពេលមានស្រាប់ ហើយប្រើក្នុង rm ដើម្បីលុប Folder រួមទាំងឯកសារខាងក្នុងទាំងអស់។

3. FS Synchronous vs FS Asynchronous:

ក្នុងការអភិវឌ្ឍ Web Server ពិតប្រាកដ គេប្រើ Asynchronous (ប្រហែល 95%) ច្រើនជាង Synchronous ដាច់ឆ្ងាយ ព្រោះ Node.js ដំណើរការលើ Single Thread ដែល Asynchronous ជួយការពារកុំឱ្យ Server ជាប់គាំង (Blocking) ពេលមានអ្នកប្រើប្រាស់ច្រើននាក់ចូលមកព្រមគ្នា។

4. Syntax (ទម្រង់កូដ Async Callback គ្រប់ Methods):

const fs = require('fs');

// 1. បង្កើត Folder (Create Folder)
fs.mkdir('data', { recursive: true }, (err) => console.log('បង្កើត Folder រួច!'));

// 2. បង្កើត និងសរសេរចូល File (Create / Write)
fs.writeFile('data/user.txt', 'ឈ្មោះ៖ សុខា\n', (err) => console.log('សរសេរ File រួច!'));

// 3. សរសេរបន្ថែមទិន្នន័យ (Update / Append)
fs.appendFile('data/user.txt', 'វគ្គ៖ Node.js', (err) => console.log('Update រួច!'));

// 4. អានទិន្នន័យពី File (Read)
fs.readFile('data/user.txt', 'utf8', (err, data) => console.log(data));

// 5. លុប File និង Folder (Delete)
fs.unlink('data/user.txt', (err) => console.log('លុប File រួច!'));
fs.rm('data', { recursive: true }, (err) => console.log('លុប Folder រួច!'));
5. Summary (សង្ខេបមេរៀន)៖ FS Asynchronous គឺជាវិធីគ្រប់គ្រង File និង Folder ដោយមិនរង់ចាំកិច្ចការចប់សិនឡើយ (Non-blocking) តាមរយៈ Methods ដែលគ្មានពាក្យ Sync និងប្រើ Callback ដើម្បីទទួលលទ្ធផល។

Node.js & Express.js 8. Built-in HTTP Server

8. ការបង្កើត Web Server ដំបូងដោយប្រើ HTTP Module

1. Definition (និយមន័យ):

HTTP Module គឺជា Built-in Module របស់ Node.js ដែលប្រើសម្រាប់បង្កើត Web Server ដើម្បីទទួលសំណើ (Request) ពីអ្នកប្រើប្រាស់ និងបញ្ជូនទិន្នន័យត្រឡប់ទៅវិញ (Response)។

2. មុខងារ និង Methods សំខាន់ៗ:

  • http.createServer((req, res) => {}) (បង្កើត Server)៖ បង្កើតកម្មវិធី Server សម្រាប់ទទួលសំណើ (req) និងឆ្លើយតប (res)។
  • res.writeHead(200, { 'Content-Type': '...' }) (កំណត់ Status & Header)៖ កំណត់លេខកូដស្ថានភាព (200) និងប្រភេទទិន្នន័យបញ្ចូលគ្នាតែមួយបន្ទាត់៖
    • 'text/plain' — ផ្ញើទិន្នន័យជាអត្ថបទធម្មតា (Plain Text)។
    • 'text/html' — ផ្ញើទិន្នន័យជាកូដ HTML (Web Page)។
    • 'application/json' — ផ្ញើទិន្នន័យជាទម្រង់ JSON (សម្រាប់ API)។
  • res.write(data) (សរសេរទិន្នន័យ)៖ សរសេរ ឬផ្ញើទិន្នន័យបញ្ជូនទៅ Client ម្តងបន្តិចៗមុនពេលបិទ។
  • res.end(data) (បញ្ចប់ការឆ្លើយតប)៖ បញ្ជូនទិន្នន័យចុងក្រោយ និងបិទការតភ្ជាប់ (ប្រើ JSON.stringify() ដើម្បីផ្ញើជា JSON)។
  • server.listen(3000) (បើកដំណើរការ Port)៖ កំណត់លេខ Port (ឧ. 3000) ដើម្បីឱ្យ Server រង់ចាំទទួលសំណើ។

Parameters ស្នូលទាំង ២ ក្នុង Server៖

  • req (ទទួលសំណើ)៖ ផ្ទុកព័ត៌មានសំណើដែលផ្ញើមកពីអ្នកប្រើប្រាស់ (URL, Method, Headers)។
  • res (ឆ្លើយតបទិន្នន័យ)៖ ប្រើសម្រាប់រៀបចំ និងបញ្ជូនទិន្នន័យត្រឡប់ទៅអ្នកប្រើប្រាស់វិញ។

3. Syntax (ទម្រង់កូដ):

const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ message: "សួស្តីពី Node.js HTTP Server!" }));
});

server.listen(3000, () => {
  console.log("Server កំពុងដំណើរការនៅ http://localhost:3000");
});

5. Summary (សង្ខេបមេរៀន)៖ HTTP Module ប្រើសម្រាប់បង្កើត Web Server ទទួល req និងឆ្លើយតប res ប៉ុន្តែពេលមាន Routes ច្រើនវាស្មុគស្មាញ ទើបគេប្រើ Express.js មកជំនួស។

Node.js & Express.js 9. HTTP Status Codes

9. HTTP Status Codes (លេខកូដស្ថានភាព)

1. Definition (និយមន័យ):

HTTP Status Code គឺជាលេខកូដ ៣ ខ្ទង់ដែល Server បញ្ជូនត្រឡប់ទៅឱ្យ Client (Browser/Frontend) ដើម្បីបញ្ជាក់ថាសំណើ (Request) នោះទទួលបានជោគជ័យ ឬជួបបញ្ហា Error អ្វីមួយ។

2. ក្រុមលេខកូដសំខាន់ៗដែលត្រូវស្គាល់៖

  • 2xx (ជោគជ័យ - Success):
    • 200 OK — ទាញយក ឬកែប្រែទិន្នន័យបានជោគជ័យ។
    • 201 Created — បង្កើតទិន្នន័យថ្មីជោគជ័យ (ឧ. ចុះឈ្មោះ ឬបន្ថែមទំនិញថ្មី)។
    • 204 No Content — ដំណើរការជោគជ័យ តែគ្មានទិន្នន័យត្រឡប់មកវិញ (ឧ. លុបទិន្នន័យរួច)។
  • 4xx (កំហុសខាង Client / អ្នកប្រើប្រាស់):
    • 400 Bad Request — ទិន្នន័យដែលផ្ញើមកមិនត្រឹមត្រូវ ឬខ្វះព័ត៌មាន។
    • 401 Unauthorized — មិនទាន់បាន Login ឬគ្មាន Token ត្រឹមត្រូវ។
    • 403 Forbidden — Login រួចហើយ តែគ្មានសិទ្ធិចូលប្រើ (ឧ. User ធម្មតាចូលទំព័រ Admin)។
    • 404 Not Found — រកមិនឃើញទីតាំង URL ឬទិន្នន័យដែលចង់បាន។
  • 5xx (កំហុសខាង Server):
    • 500 Internal Server Error — កូដខាង Server មានបញ្ហា ឬគាំង (Bug)។
    • 503 Service Unavailable — Server កំពុងបិទជួសជុល ឬផ្ទុកលើសចំណុះ។

3. Syntax (ឧទាហរណ៍ការកំណត់ Status Code ក្នុង Server):

const http = require('http');

const server = http.createServer((req, res) => {
  if (req.url === '/api/users') {
    // របៀបទី ១៖ សរសេរ Status Code ដាច់ដោយឡែក
    res.statusCode = 200;
    res.setHeader('Content-Type', 'application/json');
    res.end(JSON.stringify({ status: "Success", data: [] }));
  } else {
    // របៀបទី ២៖ សរសេរ Status Code លាយជាមួយ Header តែមួយបន្ទាត់
    res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify({ error: "រកមិនឃើញទំព័រនេះទេ (404)" }));
  }
});

server.listen(3000);
6. Summary (សង្ខេបមេរៀន)៖ របៀបចំណាំ៖ លេខផ្តើមដោយ 2 = ជោគជ័យ, 4 = កំហុសអ្នកប្រើប្រាស់ (Client), និង 5 = កំហុសកូដ Server (Backend)។

Node.js & Express.js 10. Introduction to Express.js

10. សេចក្តីផ្តើមអំពី Express.js & ការរៀបចំ Structure គម្រោង

1. Definition (និយមន័យ):

Express.js គឺជា Web Application Framework ដ៏ពេញនិយមបំផុតរបស់ Node.js ដែលជួយឱ្យការបង្កើត Server, ការគ្រប់គ្រង Routing និងការសរសេរ REST API មានភាពងាយស្រួល ខ្លី និងមានរបៀបរៀបរយ។

2. ការដំឡើង និងសមាសធាតុសំខាន់ៗ:

  • npm install express (ដំឡើង Express)៖ ដំឡើង Express.js ចូលក្នុង Project តាមរយៈ Terminal ជាមុនសិន។
  • const app = express() (បង្កើត App)៖ ចាប់ផ្តើមបង្កើត Instance របស់ Express ដើម្បីកំណត់ Routes និង Middleware។
  • res.json(data) (ឆ្លើយតប JSON)៖ បំប្លែង JavaScript Object ទៅជាទម្រង់ JSON ដោយស្វ័យប្រវត្តិ (ងាយជាង http សុទ្ធ)។
  • app.listen(PORT, () => {}) (បើក Server)៖ ចាប់ផ្តើមដំណើរការ Express Server លើ Port ដែលកំណត់។

រចនាសម្ព័ន្ធ Folder ស្តង់ដារក្នុង Express៖

  • routes/ ៖ កំណត់ និងបំបែកផ្លូវ URL (Endpoints) របស់ API។
  • controllers/ ៖ ផ្ទុក Functions សម្រាប់ដោះស្រាយ Logic តាមមុខងារ។
  • models/ ៖ កំណត់រចនាសម្ព័ន្ធទិន្នន័យ (Schema) សម្រាប់ Database។
  • config/ ៖ ផ្ទុកការកំណត់ផ្សេងៗ ដូចជាការតភ្ជាប់ទៅកាន់ Database។
  • server.js (Entry Point)៖ ឯកសារមេសម្រាប់ដំណើរការកម្មវិធីទាំងមូល។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលបង្កើត Backend REST API ជាមួយ React, Next.js ឬ Mobile App ជំនួសឱ្យការប្រើ http module សុទ្ធរបស់ Node.js។

4. Syntax (ទម្រង់កូដបង្កើត Server ជាមួយ Express.js):

const express = require('express');
const app = express();

app.get('/', (req, res) => {
  res.json({ status: "success", message: "ស្វាគមន៍មកកាន់ Express API!" });

5. Summary (សង្ខេបមេរៀន)៖ Express.js គឺជា Framework របស់ Node.js ដែលកាត់បន្ថយកូដស្មុគស្មាញ ដោយផ្តល់នូវ app.get() និង res.json() សម្រាប់បង្កើត REST API បានយ៉ាងរហ័ស។

Node.js & Express.js 11. Routing & HTTP Methods

11. ការគ្រប់គ្រង Routing & HTTP Methods

1. Definition (និយមន័យ):

Routing គឺជាការកំណត់ផ្លូវ (URL Endpoints) និងវិធីសាស្ត្រស្នើសុំ (HTTP Methods) ដើម្បីឱ្យ Server ដឹងថាត្រូវឆ្លើយតបបែបណានៅពេលអ្នកប្រើប្រាស់ចូលទៅកាន់ URL ណាមួយ។

2. មុខងារ និង HTTP Methods សំខាន់ៗ:

  • app.method(path, handler) (ទម្រង់ Route)៖ កំណត់ HTTP Method ផ្លូវ URL និង Function សម្រាប់ឆ្លើយតប។
  • :id (Dynamic Route Parameter)៖ កំណត់ទីតាំង ID ប្រែប្រួលនៅក្នុងផ្លូវ URL (ឧ. /api/courses/:id)។

HTTP Methods ទាំង ៤ របស់ REST API (CRUD)៖

  • app.get() (GET - Read)៖ ប្រើសម្រាប់អាន ឬទាញទិន្នន័យពី Server។
  • app.post() (POST - Create)៖ ប្រើសម្រាប់បញ្ជូនទិន្នន័យថ្មីទៅរក្សាទុកក្នុង Server។
  • app.put() (PUT - Update)៖ ប្រើសម្រាប់កែប្រែព័ត៌មានដែលមានស្រាប់តាមរយៈ ID។
  • app.delete() (DELETE - Delete)៖ ប្រើសម្រាប់លុបទិន្នន័យចេញពី Server។

3. Syntax (ទម្រង់កូដ):

app.get('/api/courses', (req, res) => {
  res.json([{ id: 1, title: "HTML & CSS" }, { id: 2, title: "Node.js" }]);
});

app.post('/api/courses', (req, res) => {
  res.status(201).json({ message: "បង្កើតមុខវិជ្ជាថ្មីបានជោគជ័យ!" });
});

app.put('/api/courses/:id', (req, res) => {
  res.json({ message: "កែប្រែជោគជ័យ!" });
});

app.delete('/api/courses/:id', (req, res) => {
  res.json({ message: "លុបជោគជ័យ!" });
});

4. Output (លទ្ធផលនៅលើ Postman):

POST http://localhost:5000/api/courses — 201 Created
{"message": "បង្កើតមុខវិជ្ជាថ្មីបានជោគជ័យ!"}
5. Summary (សង្ខេបមេរៀន)៖ Routing គឺជាការកំណត់ផ្លូវ URL និងវិធីសាស្ត្រឆ្លើយតបរបស់ Server ដោយប្រើ HTTP Methods ឱ្យត្រូវតាមមុខងារ៖ GET (អាន), POST (បង្កើត), PUT (កែប្រែ) និង DELETE (លុប)។

Node.js & Express.js 12. Request Data (Params, Query, Body)

12. ការចាប់ទិន្នន័យពី Request (req.params, req.query, req.body)

1. Definition (និយមន័យ):

នៅពេល Frontend ឬ Postman ផ្ញើសំណើមកកាន់ Server ទិន្នន័យទាំងអស់ត្រូវបានផ្ទុកនៅក្នុង Object req (Request) ដែលយើងអាចទាញយកតាម ៣ របៀបសំខាន់ៗ។

2. មុខងារ និងវិធីចាប់ទិន្នន័យសំខាន់ៗ:

  • app.use(express.json()) (JSON Parser)៖ ចាំបាច់ត្រូវបើកជាមុន ដើម្បីឱ្យ Express អាចអានទិន្នន័យក្នុង req.body បាន។
  • Object Destructuring៖ ទាញយក Properties ចេញពី req.body យ៉ាងខ្លី (ឧ. const { name, email } = req.body)។

ប្រភពទិន្នន័យទាំង ៣ ក្នុង Request Object៖

  • req.params (Route Parameters)៖ ចាប់តម្លៃដែលភ្ជាប់ក្នុងផ្លូវ URL ផ្ទាល់ (ឧ. /users/:id ➔ req.params.id)។
  • req.query (Query Strings)៖ ចាប់តម្លៃស្វែងរកនៅខាងក្រោយសញ្ញា ? (ឧ. /search?role=admin ➔ req.query.role)។
  • req.body (Request Body)៖ ចាប់ទិន្នន័យ JSON ដែលផ្ញើតាម POST ឬ PUT។

3. ប្រើពេលណា (When to Use):

ប្រើ params ពេលចង់មើល ឬលុបទិន្នន័យតាម ID ជាក់លាក់, ប្រើ query ពេលធ្វើមុខងារ Search/Filter និងប្រើ body ពេលទទួលទិន្នន័យចុះឈ្មោះ ឬបង្កើតថ្មី។

4. Syntax (ទម្រង់កូដ):

app.use(express.json()); // ចាំបាច់សម្រាប់អាន req.body

app.get('/api/users/:id', (req, res) => {
  res.json({ userId: req.params.id, keyword: req.query.role });
});

app.post('/api/users', (req, res) => {
  const { name, email } = req.body;
  res.json({ received: { name, email } });
});

5. Output (លទ្ធផលនៅលើ Postman):

GET http://localhost:5000/api/users/101?role=admin
{"userId": "101", "keyword": "admin"}
6. Summary (សង្ខេបមេរៀន)៖ ការទាញយកទិន្នន័យពី Object req ចែកចេញជា ៣ របៀប៖ ប្រើ req.params សម្រាប់ចាប់ ID, ប្រើ req.query សម្រាប់ Filter/Search និងប្រើ req.body សម្រាប់ទទួលទិន្នន័យ Form ឬ JSON។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 14
Node.js & Express.js 13. Middleware in Express.js

13. ការប្រើប្រាស់ Middleware (express.json, Custom, CORS)

1. Definition (និយមន័យ):

Middleware គឺជា Function កណ្តាលដែលដំណើរការនៅចន្លោះពេល Server ទទួលបាន Request និងមុនពេលបញ្ជូន Response ត្រឡប់ទៅវិញ។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • app.use(middleware) (បើកប្រើ Middleware)៖ កំណត់ឱ្យ Middleware ដំណើរការលើគ្រប់ Requests ទាំងអស់។
  • next() (បន្តដំណើរការ)៖ ជា Function សម្រាប់ប្រាប់ Express ឱ្យបន្តទៅកាន់ Route ឬ Middleware បន្ទាប់ (បើភ្លេចហៅ កម្មវិធីនឹងគាំង)។

ប្រភេទ Middleware ទាំង ៣ ក្នុង Express.js៖

  • Built-in Middleware៖ ភ្ជាប់មកស្រាប់ក្នុង Express (ឧ. express.json() សម្រាប់អានទិន្នន័យ JSON)។
  • Third-party Middleware៖ ដំឡើងបន្ថែមតាម NPM (ឧ. cors() ដើម្បីអនុញ្ញាតឱ្យ Frontend ភ្ជាប់មក API)។
  • Custom Middleware៖ សរសេរដោយខ្លួនឯង (req, res, next) => {} សម្រាប់ពិនិត្យ Token (Auth) ឬ Log។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលត្រូវការបើកសិទ្ធិ CORS ឱ្យ Frontend ភ្ជាប់មក, អាន JSON Body, ពិនិត្យ Token សុវត្ថិភាព (Authentication) ឬកត់ត្រាប្រវត្តិ Requests។

4. Syntax (ទម្រង់កូដបង្កើត Custom Middleware):

const cors = require('cors');
app.use(cors());
app.use(express.json());

const logger = (req, res, next) => {
  console.log(`[${new Date().toLocaleTimeString()}] ${req.method} ${req.url}`);
  next(); // បើភ្លេចហៅ next() នោះ Request នឹងគាំងត្រឹមនេះ!
};

app.use(logger);

5. Output (លទ្ធផលនៅលើ Terminal):

Terminal — Middleware Log
[10:15:30 AM] GET /api/courses
[10:15:42 AM] POST /api/users
6. Summary (សង្ខេបមេរៀន)៖ Middleware គឺជា Function កណ្តាលចន្លោះ Request និង Response ដែលដំណើរការតាមរយៈ app.use() សម្រាប់អាន JSON, បើក cors() ឬពិនិត្យសិទ្ធិ ហើយត្រូវហៅ next() ជានិច្ច។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 15
Node.js & Express.js 14. MVC Pattern (Routes & Controllers)

14. ការរៀបចំកូដតាមគំរូ MVC (Routes & Controllers)

1. Definition (និយមន័យ):

MVC (Model - View - Controller) គឺជាការរៀបចំរចនាសម្ព័ន្ធកូដ Backend ដោយបំបែកផ្នែកកំណត់ផ្លូវ (Routes) ផ្នែកដោះស្រាយតក្កវិជ្ជា (Controllers) និងផ្នែកទិន្នន័យ (Models) ដាច់ពីគ្នា។

2. មុខងារ និងសមាសធាតុសំខាន់ៗ:

  • express.Router() (បង្កើត Route)៖ ជួយបំបែកផ្លូវ API តាមក្រុមមុខងារ (ឧ. userRoutes.js, productRoutes.js)។
  • app.use('/api/products', router) (ភ្ជាប់ Route)៖ កំណត់ Prefix URL រួមសម្រាប់ភ្ជាប់ Route ចូលក្នុង server.js។

តួនាទីសំខាន់ៗក្នុង MVC Architecture៖

  • Model៖ គ្រប់គ្រងរចនាសម្ព័ន្ធទិន្នន័យ និងការតភ្ជាប់ជាមួយ Database (Mongoose Schema)។
  • Controller៖ ផ្ទុក Functions សម្រាប់ដំណើរការតក្កវិជ្ជា និងរៀបចំទិន្នន័យឆ្លើយតបទៅ Client។
  • Route (ជំនួស View ក្នុង REST API)៖ កំណត់ URL Endpoints ហើយបញ្ជូនសំណើទៅកាន់ Controller។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលគម្រោង API ចាប់ផ្តើមមាន Endpoints ច្រើន (ដូចជា Users, Products, Orders) ដើម្បីកុំឱ្យកូដទាំងអស់គរនៅក្នុង server.js តែមួយ។

4. Syntax (ទម្រង់កូដបំបែក Controller និង Route):

// 1. controllers/productController.js
const getProducts = (req, res) => {
  res.json([{ id: 1, name: "Laptop Dell" }]);
};
module.exports = { getProducts };

// 2. routes/productRoutes.js
const router = require('express').Router();
const { getProducts } = require('../controllers/productController');
router.get('/', getProducts);
module.exports = router;

5. Output (ការភ្ជាប់ក្នុង server.js និងលទ្ធផល):

GET http://localhost:5000/api/products
// server.js: app.use('/api/products', require('./routes/productRoutes'));
[{"id": 1, "name": "Laptop Dell"}]
6. Summary (សង្ខេបមេរៀន)៖ MVC គឺជាការបំបែកកូដជាផ្នែកៗដោយប្រើ express.Router() និង Controllers ដើម្បីឱ្យគម្រោងធំៗងាយស្រួលថែទាំ និងធ្វើការងារជាក្រុមបានរលូន។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 16

15. ការគ្រប់គ្រងអថេរសម្ងាត់ជាមួយ Environment Variables (.env)

1. Definition (និយមន័យ):

Environment Variables (.env) គឺជាឯកសារពិសេសសម្រាប់រក្សាទុកព័ត៌មានសម្ងាត់ និងការកំណត់ប្រព័ន្ធ ដូចជាលេខ Port, Database URL, និង API Keys ដោយមិនសរសេរចូលក្នុងកូដផ្ទាល់។

  • ការពារលើ GitHub (.gitignore)៖ ត្រូវបន្ថែម .env ចូលក្នុង .gitignore ជានិច្ច ដើម្បីកុំឱ្យបែកធ្លាយពាក្យសម្ងាត់។

Terminal — bash
$ node server.js

Node.js & Express.js 16. Connecting MongoDB Database with Mongoose

16. ការតភ្ជាប់ Express.js ទៅកាន់ MongoDB Database (Mongoose)

1. Definition (និយមន័យ):

Mongoose គឺជា ODM (Object Data Modeling) Library សម្រាប់តភ្ជាប់ Node.js/Express.js ទៅកាន់ MongoDB Database និងជួយកំណត់រចនាសម្ព័ន្ធទិន្នន័យ (Schema) ឱ្យមានស្តង់ដារច្បាស់លាស់។

2. មុខងារ និង Methods សំខាន់ៗ:

  • mongoose.connect(uri) (តភ្ជាប់ Database)៖ ភ្ជាប់ Server ទៅកាន់ MongoDB Compass (Local) ឬ MongoDB Atlas (Cloud)។
  • new mongoose.Schema({...}, {...}) (បង្កើតគំរូទិន្នន័យ)៖ កំណត់ឈ្មោះ Fields, ប្រភេទទិន្នន័យ (String, Number, Boolean) និងលក្ខខណ្ឌ (required)។
  • mongoose.model('Name', schema) (បង្កើត Model)៖ បង្កើត Collection ក្នុង Database ដើម្បីយកទៅប្រើសម្រាប់ប្រតិបត្តិការ CRUD។

ជម្រើសបន្ថែមក្នុង Schema (Schema Options)៖

  • { timestamps: true } ៖ បន្ថែម createdAt និង updatedAt ដោយស្វ័យប្រវត្តិរាល់ពេលបង្កើត ឬកែប្រែទិន្នន័យ។
  • { versionKey: false } ៖ បិទមិនឱ្យបង្ហាញ Field __v (Version Key) នៅក្នុងឯកសារទិន្នន័យ។

3. ប្រើពេលណា (When to Use):

ប្រើនៅពេលត្រូវការរក្សាទុកទិន្នន័យជាអចិន្ត្រៃយ៍ (Persistent Storage) ក្នុង MongoDB Database ជំនួសឱ្យការទុកទិន្នន័យបណ្តោះអាសន្នក្នុង Array នៃកូដ។

4. Syntax (ទម្រង់កូដតភ្ជាប់ និងបង្កើត Model):

const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    await mongoose.connect(process.env.MONGO_URI);
    console.log("តភ្ជាប់ MongoDB Database បានជោគជ័យ!");
  } catch (err) {
    console.error("បរាជ័យ៖", err);
  }
};
connectDB();

const studentSchema = new mongoose.Schema({
  name: { type: String, required: true },
  age: Number,
  course: String
}, { timestamps: true });

const Student = mongoose.model('Student', studentSchema);
6. Summary (សង្ខេបមេរៀន)៖ Mongoose គឺជា ODM Library ដែលដំឡើងតាម npm install mongoose រួចប្រើ mongoose.connect() ដើម្បីភ្ជាប់ទៅកាន់ MongoDB Database និងបង្កើត Schema សម្រាប់គ្រប់គ្រងទិន្នន័យ។
រៀបចំដោយ៖ លាត ប្រុស ទំព័រ 18
Node.js & Express.js 17. Full CRUD API Operations

17. ការបង្កើត CRUD API ពេញលេញ (Create, Read, Update, Delete)

1. Definition (និយមន័យ):

CRUD មកពីពាក្យ Create (បង្កើត), Read (អាន), Update (កែប្រែ) និង Delete (លុប) ដែលជាប្រតិបត្តិការស្នូលទាំង ៤ របស់ Backend API ជាមួយ Database ដោយប្រើ async / await។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • async / await (Asynchronous)៖ ប្រើសម្រាប់រង់ចាំឱ្យ Database ដំណើរការចប់សព្វគ្រប់ មុននឹងបន្តទៅបន្ទាត់កូដបន្ទាប់។
  • { new: true } (Return Updated Data)៖ កំណត់ឱ្យ Mongoose ត្រឡប់ទិន្នន័យថ្មីដែលទើបកែប្រែរួចមកវិញ។

Mongoose CRUD Methods ទាំង ៤ ប្រភេទ៖

  • C - Create៖ Model.create(req.body) បង្កើត និងរក្សាទុកទិន្នន័យថ្មីចូល MongoDB។
  • R - Read៖ Model.find() ទាញបញ្ជីទិន្នន័យទាំងអស់ (ឬ Model.findById(id) សម្រាប់ទិន្នន័យមួយ)។
  • U - Update៖ Model.findByIdAndUpdate(id, req.body, { new: true }) កែប្រែទិន្នន័យតាម ID។
  • D - Delete៖ Model.findByIdAndDelete(id) លុបទិន្នន័យចេញពី Database តាម ID។

3. Syntax (ទម្រង់កូដ Controller ពេញលេញ):

app.post('/api/students', async (req, res) => {
  const student = await Student.create(req.body);
  res.status(201).json(student);
});

app.get('/api/students', async (req, res) => {
  res.json(await Student.find());
});

app.put('/api/students/:id', async (req, res) => {
  const updated = await Student.findByIdAndUpdate(req.params.id, req.body, { new: true });
  res.json(updated);
});

app.delete('/api/students/:id', async (req, res) => {
  await Student.findByIdAndDelete(req.params.id);
  res.json({ message: "លុបទិន្នន័យសិស្សរួចរាល់!" });
});

4. Output (លទ្ធផលនៅលើ Postman):

POST http://localhost:5000/api/students — 201 Created
{"_id": "673a91f8b2c4e", "name": "ចាន់ ដារ៉ា", "age": 20, "course": "Web Dev"}
5. Summary (សង្ខេបមេរៀន)៖ CRUD (Create, Read, Update, Delete) ប្រើ async / await រួមជាមួយ .create(), .find(), .findByIdAndUpdate() និង .findByIdAndDelete() ដើម្បីគ្រប់គ្រងទិន្នន័យក្នុង Database ទាំងស្រុង។

Node.js & Express.js 18. Error Handling & HTTP Status Codes

18. ការគ្រប់គ្រង Error Handling និង HTTP Status Codes

1. Definition (និយមន័យ):

Error Handling គឺជាការចាប់កំហុសដែលកើតឡើងក្នុងពេលដំណើរការ Server (ដូចជា ID ខុសទម្រង់ ឬ Database ដាច់) ដើម្បីកុំឱ្យ Server គាំង (Crash) និងបញ្ជូនសារប្រាប់អ្នកប្រើប្រាស់វិញឱ្យបានត្រឹមត្រូវ។

2. មុខងារ និងពាក្យគន្លឹះសំខាន់ៗ:

  • try { ... } catch (error) { ... } (ចាប់កំហុស)៖ ស្រោបកូដ async / await ដើម្បីចាប់យកកំហុសមកដោះស្រាយដោយសុវត្ថិភាព។
  • res.status(code).json(...) (បញ្ជូន Status Code)៖ កំណត់លេខកូដស្ថានភាព HTTP ភ្ជាប់ជាមួយសារ JSON ត្រឡប់ទៅ Client។

លេខកូដកំហុស (Error Status Codes) សំខាន់ៗ៖

  • 400 Bad Request (ទិន្នន័យខុស)៖ Client បញ្ចូលទិន្នន័យខ្វះ ឬខុសលក្ខខណ្ឌ។
  • 404 Not Found (រកមិនឃើញ)៖ ផ្លូវ URL ឬ ID ទិន្នន័យដែលស្វែងរកមិនមានក្នុងប្រព័ន្ធ។
  • 500 Internal Server Error (កំហុស Server)៖ កំហុសបច្ចេកទេសខាង Server ឬ Database ដាច់ការតភ្ជាប់។

3. ប្រើពេលណា (When to Use):

ប្រើគ្រប់ពេលសរសេរកូដ async / await ជាមួយ Database ដើម្បីការពារកុំឱ្យ Server រលត់ពេលមានបញ្ហា និងជួយឱ្យ Frontend ដឹងពីមូលហេតុនៃកំហុសច្បាស់លាស់។

4. Syntax (ទម្រង់កូដ try...catch):

app.get('/api/students/:id', async (req, res) => {
  try {
    const student = await Student.findById(req.params.id);
    if (!student) {
      return res.status(404).json({ message: "រកមិនឃើញទិន្នន័យសិស្សនេះទេ!" });
    }
    res.status(200).json(student);
  } catch (error) {
    res.status(500).json({ message: "មានបញ្ហា Server៖", error: error.message });
  }
});

5. Output (លទ្ធផលនៅលើ Postman ពេលរកមិនឃើញ ID):

GET http://localhost:5000/api/students/673a91f8b2c4e00000000000 — 404 Not Found
{"message": "រកមិនឃើញទិន្នន័យសិស្សនេះទេ!"}
6. Summary (សង្ខេបមេរៀន)៖ Error Handling គឺជាការចាប់កំហុសកុំឱ្យ Server គាំង ដោយស្រោបកូដ async / await ក្នុង try...catch និងបញ្ជូន res.status() (400, 404, 500) ឱ្យត្រូវតាមស្ថានភាពជាក់ស្តែង។
